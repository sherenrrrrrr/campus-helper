2. docs/product-spec-v2.md：用户提供的 Claude 产品方案。
3. docs/schema.md：真实实现的数据结构和对方案矛盾的处理。
4. PRODUCT.md、DESIGN.md、AGENTS.md：项目边界、视觉系统和设计技能约定。
5. outputs/产品功能待办.md：用户后来补充的想法，仅记录，明确要求先不实现。

## 重要规则差异

- 首次发布的首份证明存疑时转管理员复核，不能直接拒绝；与产品方案验收中“首份直接拒绝”存在冲突，采用保护规则。
- 被拒绝后保留 7 天奖励额度和名额，申诉中继续保留，避免拒绝名额立即回流导致超卖或申诉发奖缺口。
- 停止或下架任务后，在途审核和申诉结清才退剩余预算，已通过的劳动报酬不回滚。
- 截图缩略图在同浏览器刷新后保留，结清 7 天后下次读取清理；不是刷新即消失。
- 积分守恒以及每个用户、任务、流水的对账，在纯函数 commit 后统一检查。

## 运行与验证

双击 outputs/campus-helper-demo.html 可体验。开发时运行：

```sh
node scripts/serve.cjs
node --test tests/model.test.cjs
node scripts/build.cjs
```

本地服务默认 http://127.0.0.1:4173 。原聊天预览使用 4174 端口，不能假设新机器上这个进程还在。

修改源码后重新 build，生成单文件与 dist/index.html。源码入口 prototype/index.html，规则在 prototype/data/points.js，样例数据在 prototype/data/seed.js，普通界面在 app.js，管理员界面在 admin.js。

最后一次验证：18 项规则测试通过；本机 Chrome 下 1440px 和 390px 的发布、提交、审核、申诉、发奖、超时和重置流程通过；独立 HTML 打开通过。tests/browser-smoke.cjs 需要另行提供 Playwright 和 Chrome，设置 PLAYWRIGHT_MODULE / PREVIEW_URL 可指定本地环境；它不是零依赖测试。未在实体手机上验证键盘弹出。
